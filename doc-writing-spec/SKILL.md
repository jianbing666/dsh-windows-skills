# 文档写作规范（doc-writing-spec）

## 核心原则

1. **先问格式与字数，再动笔。** 开工前确认输出格式（Markdown / Word / PDF）、预期中文字数区间、是否需要目录与图表。格式与字数是返工成本最高的两个变量，先锁死能省掉整轮重写。
2. **正文以段落为主。** 介绍与说明用连贯段落承载，不做条目堆砌；多个段落并列时，每段配一个小标题，而不是揉成一大段。
3. **分节列出大小标题。** 一级用「一、二、三」，二级用「1.1 / 1.2」；标题下是段落，不是清单。
4. **每 1~2 节配一张表。** 仅当需要数据对比时用表格（薪酬、时间线、维度对照），密度控制在每 1~2 个节一张，不要通篇表格。
5. **表格之外用文字辅助说明。** 表格只承载数据维度，结论、原因、例外与口径写在表格前后的段落里。
6. **少用列表。** 能写成句子就不分点，只有确实并列且简短时才用列表。

## 标准流程

1. **接单三问**：输出格式？预期字数？用途与读者？
2. **先出骨架**：把目录或标题结构先给用户确认，返回成本低、返工少。
3. **按节填充**：段落为主，需要对比的小节配表，并补上文字说明。
4. **交付前自检**：中文字数是否落在区间内、是否以段落为主、表格密度是否合适。

## 自检清单

- [ ] 格式与字数是否符合用户要求？
- [ ] 是否以段落为主，而非条目堆砌？
- [ ] 大小标题是否分层清晰？
- [ ] 表格是否只用于数据对比，且密度为每 1~2 节一张？
- [ ] 表格外是否有文字说明结论与口径？

## 常见返工

- 未确认格式与字数就动笔，交付远超预期的长文。
- 通篇堆表格，缺少段落叙述。
- 通篇段落没有小标题，阅读时找不到结构。
- 详细版与精简版混在同一份文档里，读者分不清该看哪一版。
