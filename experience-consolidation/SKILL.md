# 经验固化（Experience Consolidation）

## 触发条件（先分级，再决定投入）
> **快速判据（权威表见下）：T0（笔误/拼写，一眼可修）→ 直接修、不记录，就此停止阅读本技能；T1（只属当前项目、一次解决）→ 项目 `TROUBLESHOOTING.md` 记一条简版（**会重复踩、需要判据**的再进 `<workspace>/.dsh/pitfalls/`，见「双层库」）；T2（≥2 次 / 阻塞 >10 分钟 / 修复 A 引发 B / DSH 跨项目共性）→ 读下去，走完整 SOP。**
以下任一情况出现时，先做分级判定——本技能的价值来自「重复踩坑」，不是「记录每一个错误」：
1. 命令执行报错、程序启动失败、插件加载失败。
2. 某操作在预期内应成功，但实际结果异常（如进程存在但白屏）。
3. 网络请求超时、镜像源不通、权限拒绝。
4. 修复一个问题后，引发了新的关联问题（例如修复了A导致B崩溃）。

| 级别 | 判定标准 | 动作 |
| --- | --- | --- |
| **T0 琐碎** | 一眼可见的笔误/拼写/变量名写错，一次即修好，且不具普遍性 | 直接修；**不记录、不产出文档、不建技能** |
| **T1 单次** | 需要排查但一次解决，且只属于当前项目 | 在项目 `TROUBLESHOOTING.md` 追加一条简版记录（现象 / 根因 / 命令）；**会重复踩且需要判据**的写进 `<workspace>/.dsh/pitfalls/`（项目级覆盖层，见「双层库」） |
| **T2 值得固化** | 命中任一：① 出现 ≥2 次 ② 阻塞 >10 分钟 ③ 修复 A 引发 B ④ 属 DSH 基础环境/沙箱/编码等跨项目共性 | **走完整四阶段 SOP**，并评估是否升级为独立技能 |

## 核心使命
将每次踩坑的“一次性痛苦”转化为“永久性资产”。遇到任何非预期报错，不要盲目重试，而是立即启动本 SOP：**记录现场 → 定位根因 → 验证方案 → 查重归属 → 抽象固化 → 归档入库**。

## 标准作业程序（SOP）

### 阶段一：现场保留（Capture）
- **绝对禁止**：直接要求用户重试或直接删除文件。
- **必须记录**：报错日志（含堆栈）、环境版本（Node/pnpm/DSH）、Profile 路径、权限级别（如 workspace-write / danger-full-access）。
- **量化指标**：涉及 GUI（如 Edge）必须记进程状态、端口连通性、DOM `title` 等真实指标，不靠主观猜测。
- **体量上限**：正文只保留 ≤10 行关键摘录 + 日志文件完整路径，**禁止整篇粘贴日志**。

### 阶段二：根因分析（Analyze）
- 剥离表象，寻找本质。例如：报错 `Cannot find module` 是因为版本不兼容，还是因为沙箱权限拒绝创建管道？
- 进行**最小化复现**：剥离无关业务代码，只保留触发报错的最短路径。
- 查阅官方 Issue、社区 Discussion 或已有 Skill 文档，判断是已知 Bug 还是环境特例。
- **先查已有资产**：先看工作区覆盖层 `<workspace>/.dsh/pitfalls/`（存在才读，通常 0~3 条）→ 再读 `references/index.md`（域级路由，9 行）定位域 → 只读**那一个**域文件，判断是否已有同一条——**不要**把 8 个域文件一起读进来。

### 阶段三：方案验证（Validate）
- 提出至少一个**临时绕过方案**和一个**长期修复方案**。
- 必须设立**唯一可靠的成功信号**：不要用“进程存在”，而要用“取到预期的 title / 返回体”。
- 彻底验证后，才能宣告问题解决。
- **不采信动作的自述，要回读状态**：命令「没报错」不等于动作成功。每个写操作之后**重新读回目标状态来判定**（哈希 / 内容 / 计数），而不是相信循环里那行「已…」日志。反例：2026-10-11 一次批量隔离里 17 个文件一个都没移动，脚本却报告全部成功（详见 ENV-026）。
- **彩排法**：改动**工作区之外**的真实目标前，先在**假环境**里把整条流程完整排练一遍，再申请那一次授权。做法：让 `$env:USERPROFILE` 指向一个假目录、把真实目标复制进去，跑完后对结果做**不采信脚本自述**的独立复核。本轮两次彩排各抓到一个真实 bug（`@()` 只包住管道首段导致单元素退化为字符串）。
- **判据必须与被测条目用同一个定义**：2026-10-11 实测同一文件 `Get-Content` 得 166 行、`-split "\n"` 得 167 个元素。用错定义会让判据「永远不成立」，或为迁就自己选错的测法去改判据——两者都是 ENV-026 ④ 的形态。

### 阶段三.五：技能查重（Dedup，固化前必做）
**目的**：先判「该并入谁」，再决定「怎么落盘」——同一事实只允许长在一处。**扫描范围 = `~/.dsh/skills` 下全部目录，含第三方 bundle**（它们同样占目录税、同样会撞题）。
1. **初筛（零成本，先做这步）**：技能目录的 `name` + `description` **本来就在每轮上下文里**，直接用它们判重合——多数情况到此就判完了，一个字都不用读。**防呆**：上下文里的是会话开始时的快照，本会话内改过技能目录就以磁盘为准；`whenToUse` 不在目录里，命中的候选才去读。
2. **确认（按需，只让三元组进上下文）**：对候选技能读 frontmatter 的 `name` / `description` / `whenToUse`。红线是**只把这三个字段打进输出**——读进内存不花钱，撑爆上下文的是 stdout。批量取用一条显式 UTF-8 的循环（默认读法会把中文读成乱码，见 ENV-005）：
   ```powershell
   Get-ChildItem "$env:USERPROFILE\.dsh\skills" -Directory | ForEach-Object {
     $f="$($_.FullName)\SKILL.md"; if(Test-Path $f){ "== $($_.Name)"
       $m=[regex]::Match([IO.File]::ReadAllText($f,[Text.Encoding]::UTF8),'(?s)^---\r?\n(.*?)\r?\n---')
       if($m.Success){ $m.Groups[1].Value } else { '(无 frontmatter)' } } }
   ```
   **严禁**把 `SKILL.md` 整篇 `Get-Content` 出来。字段缺失（第三方 bundle 常见）按「无描述」跳过，不报错。
3. **三档判定（判定结果必须落到动作上）**：

| 重合度 | 模式 | 动作 |
| --- | --- | --- |
| 高度重合（同一根因 / 同一命令） | **合并** | 并入已有技能正文，同步更新其 `description` / `whenToUse`（改前套「五步安全编辑」） |
| 部分重合（同域不同点） | **扩展** | 在已有技能内新增一节 + 交叉引用；正文仍只留一处 |
| 无重合 | **新建** | 仍需过「目录税」门槛（ENV-024）：不会被反复独立使用就不建 |

4. **合并冲突的裁决（并入前必查）**：新旧经验**互相否定**（同一命令 / 参数 / 结论不一致）时，先判「能否确定当前环境下的真值」——
   - **可裁决**（有验证信号或版本边界明确）→ 就地更新为真值，旧值降级成一行条件注记（如「1.20 之前用 X」），并更新该条「最后验证」日期；
   - **不可裁决**（两条都缺证据、互相否定）→ **不得强行合并**：在目标技能末尾追加 `⚠ 待人工裁决`（两条并列 + 各自验证信号 / 日期），并直接提一个二选一问题问用户；
   - 两种情况都只挂起冲突那一点，**其余不冲突的部分照常落盘**。
5. **查重失败兜底（绝不阻断固化，但也不许静默新建）**：
   - **部分读取失败** → 用**已扫到的子集**照常判定，但记账行必须**列出未扫到的技能名**（不列名字，下次照漏）。
   - **全量失败**（目录不存在 / 编码全线乱码 / 权限拒绝）→ **降级为暂存**：写 `<workspace>/.dsh/pending-pitfalls.md` 并标 `⚠ 查重失败：<原因>；未扫：<清单>`，**不新建技能、也不写归属技能**，待查重可用时补判。
   - **唯一例外**：确实 0 个技能可扫 → 按新建处理。
   - 失败日志 ≤2 行 + 原因原文，遵守体量上限。
6. **记账**：查重结论（比对了哪些技能 / 判定 / 最终落到哪个文件）在固化记录末尾留 1 行，便于追溯与事后复盘。
7. **升级信号**：技能总数 ≥ 20，或「合并 vs 扩展」出现 ≥3 次争议 → 才按需打开 `references/skill-curator-plan.md` 评估方案 B（独立 `skill-curator` 元技能）；**平时不要打开**（内容不进上下文）。

### 阶段四：抽象固化（Solidify）

**前置检查——一事一主。** 归属由**阶段三.五**判定，本节只执行落盘：已有归属就**只加指针，不复制正文**——同一事实两处维护必然漂移（改了 A，B 变陈旧却在触发时被先读到）。

问题解决后，必须判断该经验的价值：
- **如果是通用问题**：新建独立技能（如 `edge-browser-testing`），把排错过程、约束、启动脚本沉淀进它的 `SKILL.md`。**有门槛**：只有会被反复独立使用才开——技能名与描述每轮都注入目录，是固定长期成本（见 ENV-024）。
- **如果是特定环境的记录**：在当前项目的 `TROUBLESHOOTING.md` 中追加记录；**会重复踩、需要判据**的，按「双层库」写进 `<workspace>/.dsh/pitfalls/<域>.md`（作用域 `project:<名>`）。
- **如果是 DSH 基础环境问题**：更新对应的 `references/pitfalls/<域>.md` 正文（作用域 `global`），再跑 `scripts/kb-index.ps1 -Apply` 重建索引与域头清单——**不要手改 `index.md`**（B11 起它是生成物）。
- **固化格式必须包含**：
  1. 问题现象（含报错原文）
  2. 触发条件
  3. 根因剖析
  4. 最终方案（含命令或代码）
  5. 验证方法（唯一可靠信号）
  6. 适用环境 + 最后验证日期（缺省继承避坑库基线；环境变更后必须复核）
  7. 作用域：`global` 或 `project:<工作区名>`（判据见「双层库」；`promote-pending.ps1` 对缺该字段的条目直接拒收）
  8. **弯路清单**（B13 新增）：试过且**不通**的路 + 为什么不通（报错原文 / 机制上为什么不成立）。
     写成「反正不行」没有信息量，下次还会有人再试一遍；写成「X 报 YYY，因为 Z」才有用。
- **单条体量上限**：新增或修改的条目 ≤ 10 行（8 行正文 + 2 行弯路；存量超长条目在体检时压缩）；日志只留 ≤ 10 行摘录 + 日志文件路径，禁止整篇粘贴。

## 自我维护（本技能修改自身文件时）
本技能会改**自己**的 `SKILL.md`/`references/`，也会改**归属技能**（`edge-browser-testing`、`dsh-plugin-install`、`windows-msix-app-repair`）。对**所有这些技能**都必须套用**五步安全编辑**（`windows-config-safe-edit` 的四步 + 本技能补的第 2 步）：
1. **原样备份**：先 `Copy-Item` 成 `*.bak-yyyyMMdd-HHmmss`，再动笔。
2. **写盘前先断言（本技能补的第 2 步；2026-09-19 血的教训）**：所有替换在**落盘之前**完成断言——锚点必须命中、目标不得重复插入；**任一断言不过就整批放弃，绝不写一半**。
   - 断言与写盘必须是**两个阶段**：先 `throw`，再 `WriteAllText`。反例：先写后断言——守卫确实拦住了，但两个文件其实**已经改完**。
   - **删除类替换**（新串为空）**不能**用「目标已存在」当幂等守卫：空串必然「已存在」，会被误判成"已应用"。
3. **用对的工具**：读写一律显式 UTF-8（`[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)`）——PS 5.1 默认按 cp936 读无 BOM 文件会写出乱码（ENV-005）。
4. **写完严格校验**：严格 UTF-8 解码 + frontmatter 用真实 YAML 解析器（`js-yaml` 的 `load`）实测 + 条目零丢失 + 索引与正文集合一致。
5. **失败即整体还原**：任何一项不过，从备份整体还原，不要就地修补。
**红线**：frontmatter 一旦损坏，本技能会**静默从技能目录消失，且目录不提供逐条诊断**——所以第 3 步的 YAML 实测不是可选项。

**版本控制**：`~/.dsh/skills` 是 git 仓库，6 个自建技能全纳管；根级 `.gitattributes` = `* -text`（禁行尾/编码转换 → 还原即逐字节相同），`*.bak-*` 与 `*.tmp` 由 `.gitignore` 排除，第三方 bundle 逐个显式排除。
改动后 `git -C "$env:USERPROFILE\.dsh\skills" status/log/diff` 复核。历史兜底：`<workspace>\.dsh\skills-history-*.bundle`。

## 沉淀路径与批量提升（免批准暂存）
固化分两步，避免"每记一条就要一次沙箱批准"：

1. **暂存（免批准）**：T2 条目先写**工作区内**的 `<workspace>/.dsh/pending-pitfalls.md`（`workspace-write` 下可直接写），格式与避坑库条目一致。
2. **批量提升（1 次批准落 N 条）**：用户在场时**一次性**并入对应的 `references/pitfalls/<域>.md`，再跑 `scripts/kb-index.ps1 -Apply` 重建索引（`scripts/promote-pending.ps1` 已把这条流程做成一条命令，并强制校验 `作用域` 字段）；已属某技能的只写**摘要 + 指针**，其未覆盖的独有点标 `⚠ 待并入 <技能>`。
3. **记账**：提升后把条目移入暂存文件的「已提升」区并标日期，**不要删除**。

> T1（项目特有）本就不必出工作区——写项目 `TROUBLESHOOTING.md`。

## inbox：一行制兜底（踩坑**当时**就记）
**这一节的结论来自实测，反直觉但确定：收尾补卡不可靠，当场记一行才可靠。**
两次实测「收尾时补卡」都没自发发生；而「踩到坑的当时记一行」是唯一被观察到的自发路径。

三层，别混：

| 层 | 位置 | 门槛 | 谁写 |
| --- | --- | --- | --- |
| **inbox（草稿）** | `<workspace>/.dsh/inbox.md` | **一行**：现象 + 一句话解法 | 踩坑当时，随手 |
| pending（待审） | `<workspace>/.dsh/pending-pitfalls.md` | 完整 8 字段 + 作用域 | 整理时 |
| 正式库 | `references/pitfalls/<域>.md` | 过 `promote-pending.ps1` 的断言 | 提升时 |

- **什么时候记**：只要这次不是「照着已有条目做就顺了」，而是又试错了几轮 → 立刻记一行。**别等收尾**。
- **记一行也算数**：想不清楚根因就先记现象 + 临时解法，门槛是「不打断当前任务」。
- **收尾只做检查**：看一眼 inbox，够格（复发的 / 代价大的）就整理成 pending 条目，然后**删掉那一行**；小意外留着。
- **工具**：`scripts/inbox-add.ps1 -Text "…"`（写在工作区内，**不需要沙箱批准**）；插件侧是 `kb_inbox`。
- **inbox 不是知识库**：它只是「别忘」的载体。永远不整理 = 它退化成日记。

## 避坑库（索引、正文与退役）
**正文不在此处，也不在单个文件里**（B8 起按域拆分，B11 起索引是生成物）：
```text
references/
  index.md            ← 生成物：**域级路由**（一行一个域，9 行）。不逐条登记，所以体积不随条目数增长
  pitfalls/           ← 8 个域文件：powershell / sandbox / browser / plugin-install /
                        credentials / config-files / msix / publishing
  pitfalls/archive.md ← 退役区：退出常规阅读路径，**不删除**，仍可检索
```
- **查坑流程**：工作区覆盖层 `<workspace>/.dsh/pitfalls/`（存在才读，通常 0~3 条）→ `references/index.md` 定位域 → 只读**那一个**域文件。把 8 个域文件一起读进来，正是拆分要消灭的成本。
- **条目清单跟着域文件走**：每个域文件头部有一行 `> 症状：…`（索引的关键词列取它）和一个 `<!-- ec-ids:begin -->` 清单块（生成器维护）。读哪个域就顺手看到它有什么，**不需要索引再抄一遍**——旧索引正是这么坏掉的：40 行 / 4.3KB，撞上自己写的「≤40 行」上限，加一条就破约。
- **索引是生成物**：`scripts/kb-index.ps1` 从域文件重建 `index.md` 与各域头清单。`-Apply` 才写盘（先备份后回读校验），`-Check` 只判新鲜度（不一致 exit 1，`kb-health.ps1` 第 8 段直接调它）。**任何人不再手改 `index.md`**。
- **域按症状分**（沙箱权限 / PS 语义与编码 / 浏览器 / 插件与包管理 / 凭据 / 配置读写 / MSIX / 技能目录与发布），不按条目编号。
- **旧的单文件 `env-pitfalls.md` 已不存在**——留着它会变成双份真相（一处改了另一处没改，且先被读到的是旧的那份）。

## 双层库：系统级共享 / 项目级隔离
**判据只有一条：换个工作区还成立吗？** 成立 = 系统级，进全局库（所有项目共享，避免重复踩）；不成立 = 项目级，进工作区覆盖层（不外溢、不污染）。

| 层 | 位置 | 放什么 | 谁能读到 |
| --- | --- | --- | --- |
| 系统级 `global` | `~/.dsh/skills/experience-consolidation/references/` | DSH 宿主 / 沙箱 / 编码 / PS 语义 / MSIX 机制等**跨项目共性** | 所有工作区共享 |
| 项目级 `project:<名>` | `<workspace>/.dsh/pitfalls/`（同结构：`index.md` + `<域>.md`） | 只在本项目的技术栈 / 目录 / 数据 / 账号格局下成立的经验 | 只在本工作区 |

- **条目标记**：每条必写一行 `- 作用域：global ｜ 项目：—` 或 `- 作用域：project:<工作区名> ｜ 项目：<名>`。`promote-pending.ps1` 对缺该字段的条目**直接拒收**；存量条目按 `global` 推定，体检里当债务逐步补。
- **写过界就是污染**：在项目 A 里有效的修复，拿到项目 B 可能就是错误答案。项目级经验**必须**留在覆盖层，别为「也许以后有用」把它提升成 global。
- **覆盖层不是第二套机制**：格式、域划分、索引规则与全局库完全一致，`kb-index.ps1 -RefDir <workspace>/.dsh/pitfalls -Apply` 就重建项目侧索引；写它不需要沙箱批准（在工作区内）。
- **提升路径（project → global）**：同一现象在 **≥2 个工作区**出现，或确认属 DSH 基础环境（沙箱 / 编码 / 宿主机制），才提升；提升时改 `作用域：global`，并在条目里注明来源工作区。`promote-pending.ps1` 只写全局库——这正是它的定位：**提升**是跨层动作。

**体检机制**：每 +10 条或环境变更后做一次——合并重复镜像、压缩超长条目、偿还 `⚠ 待并入 <技能>` 与「缺作用域」两项债务、复核 `最后验证`、清退退役候选、跑一次 `kb-index.ps1 -Check` 确认索引没过期。
**体检工具**：`scripts/kb-health.ps1` 出报告（目录税 / 复核状态与 90 天过期 / 条目体积 / 悬空指针 / **逐文件** ENV-005 不变式 / 债务 / **退役候选** / **索引新鲜度**）；`scripts/kb-index.ps1` 重建或校验索引（`-Apply` / `-Check`）；`scripts/kb-probe.mjs` 扫真实会话日志，回答「钩子 / 读技能 / 记 inbox」到底发生了没有（**这是唯一能证伪「机制生效」的工具**）；`scripts/verify-kb.ps1` 跑 `references/verify-checks.json` 里的可执行判据，输出三态 OK / FAIL / MANUAL，并检查悬空检查项与**未知占位符**。

**退役（有生有死；B10 才补上）**：库只增不减 = 每个读者都要从头找到尾。判据必须**机械可判**，由 `kb-health.ps1` 报候选，不靠人回忆：
- **K1 冗余**：「最后验证：见 `<技能>`」（正文以该技能为准）且本库正文只剩一行「症状 → 处置」摘要；
- **K2 已自证**：`references/verify-checks.json` 中该条 kind 为 `pointer`，且目标技能真实存在。
K1 ∧ K2 → 候选；正文移入 `pitfalls/archive.md`（保留可检索性），再跑 `kb-index.ps1 -Apply`——索引会自动把该条的编号列到 archive 行，**不需要手改**。
两条硬约束：① **搬动必须与域合并同批执行**——纯指针条目整批搬走会留下空域文件（体检会直接报出哪几个会变空），所以工具**只报告、不自动搬移**；② **归档 ≠ 删除**，且**不允许因为「长期没复核」就归档**——那会按日期误杀重要条目，退役的唯一依据是「已被独立技能完全覆盖」。
**脚本用法**（ENV-027）：本机 `CurrentUser = RemoteSigned`，未签名脚本须先 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`；所有 `.ps1` 带 BOM（ENV-003）；读写一律显式 UTF-8（ENV-005）。

**已提升为独立技能的主题**（正文以该技能为准）：浏览器/无头渲染 → `edge-browser-testing`；插件安装与 profile → `dsh-plugin-install`；配置读写与编码 → `windows-config-safe-edit`；MSIX/WindowsApps → `windows-msix-app-repair`。其余条目（含 ENV-024 目录税、ENV-025 PS5.1 吞 stderr）正文在本库。

## 产出物规范
每次固化经验，必须产出以下之一：
1. 一个全新的子 Skill 目录（包含 `SKILL.md` 和相关的工具脚本）。
2. 一个更新后的 `TROUBLESHOOTING.md` 或 `EDGE-NOTES.md` 文件。
3. `references/pitfalls/<域>.md` 的条目更新 + 跑一次 `scripts/kb-index.ps1 -Apply`（索引与域头清单都是生成物，**不再手改**；`-Check` 不一致就是没跑）。
